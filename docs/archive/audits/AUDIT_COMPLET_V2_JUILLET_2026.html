🔴 Problèmes critiques identifiés 6 missions requises
# Problème Impact Gravité Fichier Mission
1 Page Login/Auth Flow incomplète
Pas de page LoginPage.jsx dédiée. Le token JWT est stocké dans localStorage sans refresh automatique. Expiration → utilisateur éjecté sans message. Pas de "Mot de passe oublié". Pas de redirection post-login selon le rôle (admin → dashboard, élève → espace élève). 		Première impression du client = catastrophique 🔴 CRITIQUE MISSION_AUTH_FLOW.md
2 UI Marketplace inexistante côté client
Le backend marketplace est 75% complet mais il n'y a PAS de page React pour : chercher des offres de cours, réserver, payer, voir le lien Jitsi, laisser un avis. Le parent doit utiliser l'API directement. MarketplacePage.jsx n'existe pas. 		Principale source de revenus = inutilisable par un client 🔴 CRITIQUE MISSION_MARKETPLACE_UI.md
3 Recherche globale Meilisearch non branchée au frontend
Meilisearch v1.8 est installé et configuré côté backend (NoteController, EleveService utilisent Scout). Mais il n'y a aucune barre de recherche globale dans le frontend React. Le directeur doit naviguer page par page pour trouver un élève, une facture, un enseignant. 		Frein majeur à la productivité quotidienne 🟠 ÉLEVÉ MISSION_RECHERCHE_GLOBALE.md
4 Page Paramètres École incomplète
ParametreController.php existe (initial commit juin 2026) mais la page frontend est basique. Manque : logo école (upload), couleurs personnalisées, horaires d'ouverture, configuration SMTP propre à l'école, gestion des niveaux scolaires custom, tarifs par défaut. 		Chaque école doit se personnaliser avant d'utiliser l'app 🟠 ÉLEVÉ MISSION_PARAMETRES_ECOLE.md
5 Onboarding / Wizard première utilisation absent
Un directeur qui s'inscrit se retrouve face à un dashboard vide sans aucune donnée. Pas de guide d'installation pas-à-pas : "1. Ajoutez vos matières → 2. Créez vos enseignants → 3. Inscrivez vos élèves → 4. Créez votre premier cours". Le taux d'abandon après inscription est probablement de 90%. 		Conversion inscription → utilisation réelle = bloquée 🟠 ÉLEVÉ MISSION_ONBOARDING.md
6 Export données et RGPD/Loi 18-07 manquants
ElevesExport.php existe pour Excel mais : pas de GDPR/18-07 export complet (droit à l'export + suppression des données), pas de "purger mes données" pour un tenant, pas d'archivage fin d'année scolaire, pas de sauvegarde exportable pour migration vers autre logiciel. Risque légal ANPDP. 		Risque légal + frein à la confiance des directeurs 🟠 ÉLEVÉ MISSION_RGPD_EXPORT.md
🟡 Problèmes secondaires À corriger dans les 30 jours
  • ⚡

    N+1 non contrôlé sur EleveController et FactureController

    Les endpoints /api/v1/eleves et /api/v1/factures n'ont pas tous leurs relations eager-loaded. Avec 500 élèves → potentiellement 500+ requêtes SQL par page. Pas détecté par les tests (BDD vide). À fixer avec ->with(['groupe', 'inscriptions', 'parents']) systématique.

  • 🔐

    Rate limiting asymétrique : login protégé, recherche non protégée

    L'IntelligentRateLimiter est sur l'API entière mais le endpoint /api/v1/marketplace/offres (public, sans auth) n'a pas de rate limiting spécifique. Un crawler peut extraire tout le catalogue en quelques secondes.

  • 📧

    Templates email : 5 créés mais pas de test de rendu réel

    Les 5 templates Blade existent mais n'ont jamais été envoyés à un vrai client email. Risque de problèmes d'encodage UTF-8 avec les caractères arabes (العربية). Pas de test avec Mailtrap pour valider le rendu cross-client (Gmail, Outlook, mobile).

  • 📊

    AnalyticsPage frontend : données hardcodées dans certains composants

    Certains graphiques du dashboard analytique affichent des valeurs "0" même quand des données existent, car l'endpoint /api/v1/analytics/dashboard n'était pas enregistré (fixé il y a 1h). À vérifier que toutes les métriques se remplissent correctement.

  • 📱

    Mobile React Native : écrans Admin incomplets

    4 écrans admin existent mais pas de navigation vers Marketplace, ni vers Prédiction IA, ni vers Signalements graves. Le directeur mobile ne peut pas gérer les situations d'urgence depuis son téléphone.

  • 💳

    Satim production : toujours en sandbox

    SATIM_BASE_URL=https://test.satim.dz dans .env.example. Aucun vrai paiement CIB/Dahabia n'est possible. Nécessite un contrat avec une banque partenaire Satim. Délai estimé : 1-2 mois après premier client signé.

🏆 Points forts exceptionnels Avantages compétitifs réels
  • 🧠

    IA Prédiction Échec Scolaire — Unique en Algérie

    Régression logistique PHP natif, 11 features, confiance 20-98%, 10 profils apprentissage, explications en français. Aucun concurrent local n'a ça. 0 dépendance externe = conforme loi 18-07.

  • 🔒

    6 niveaux de sécurité — Niveau enterprise

    RLS PostgreSQL, JWT blacklist, MFA obligatoire, audit chain HMAC-SHA256, KillSwitch MPC 2-admins, Zero Trust, Device Fingerprint, SIEM 5 règles, Honeypots. Rare pour une startup éducative.

  • 🌍

    Multitenancy réel avec isolation RLS

    BelongsToTenant sur 75+ modèles. RLS PostgreSQL en base. Un bug dans un tenant ne peut pas voir les données d'un autre. Architecture SaaS professionnelle.

  • 📱

    Triple interface : Web + Mobile + PWA

    React 19 (Vercel), React Native Expo 52 (iOS/Android), PWA offline. 4 langues : Français, Arabe, Anglais, Darija algérienne. Couverture maximale du marché local.

  • 🇩🇿

    Adapté au contexte algérien

    Curriculum officiel DZ (1AP→3AS, 7 branches BAC), ONEC (règles BEM/BAC), Satim CIB/Dahabia, IRG/CNAS barème algérien, 48 wilayas, fuseau Africa/Algiers, loi 18-07 ANPDP.
